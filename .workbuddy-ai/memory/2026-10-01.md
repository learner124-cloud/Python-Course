# 2026-10-01 — Ali's Python Course website

## What was built
Turned the folder of Obsidian lesson notes into a deployable static course site
with a saved progress bar.

- **Generator**: `tools/build_site.py` (Python + `markdown` pkg, installed in the
  managed venv `~/.workbuddy-ai/binaries/python/envs/default`).
  Converts the `.md` notes → `site/*.html`.
- **Output**: `site/` — 16 pages (index, intro, lesson-1..10, big-task-1..2,
  snake-case, comparison-operators) + `assets/style.css`, `assets/app.js`.
- **Progress tracking**: `localStorage` key `ali-python-course.progress.v1`,
  `{done: {id: timestamp}}`. Sidebar bar, topbar mini bar, per-page
  "Mark This Lesson Complete" button, confetti, 100% completion banner.
  Tracks 12 curriculum pages; the 2 reference sheets are untracked extras.
  Keyboard shortcut `C` toggles completion.
- **Theme**: dark (matches IDE theme).

## Generator details worth remembering
- Course order + page metadata live in the `COURSE` list at the top of
  `build_site.py` — adding a lesson = adding one entry.
- `obsidian_md_tweaks()` inserts blank lines before lists/headings/tables;
  Obsidian is lenient about this but Python-Markdown collapses lists into the
  preceding paragraph without it.
- `drop_leading_h1()` removes the note's own `# Lesson N:` heading (we render
  our own), `strip_obsidian_nav()` removes the hand-written prev/next lines.
- `[[Wikilinks]]` resolve through `SRC_INDEX` → real `slug.html` links.
- Callouts (`> [!tip]` etc.) become `<div class="callout tip">` blocks; note the
  `&mdash;` in titles is intentional.
- Intro is `intro.html`, NOT `index.html` — this is what lets `index.html` be
  the homepage (it was initially overwritten by the intro page; that was a bug).
- `course-manifest.json` records the canonical order + tracked ids.

## Local dev server
`python -m http.server 8000 --bind 127.0.0.1` run from inside `site/`.

## Gotcha for next time
`playwright-cli` is at `~/AppData/Roaming/npm/playwright-cli`, but **each call
is a separate process with an in-memory browser** — `open`/`resize`/`screenshot`
must be chained with `&&` in ONE Bash call, and `eval` results must be read from
the `### Result` section of the output (or redirected to a file). A fresh
session also means localStorage looks empty between calls; test persistence with
`open` + `eval` + `goto` + `eval` inside a single chained command.
